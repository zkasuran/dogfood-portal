Reproducible signed results

Hackathon results you can recompute and verify yourself.

DOGFOOD portal is a self-hostable submission and judging platform. When an organizer publishes, it emits an Ed25519-signed bundle carrying the raw scores, the method and the ranking. Anyone recomputes the winner from the raw scores then checks the signature. No trust in the host is required.

How judging works

Fair when judges differ and coverage is uneven

Reviews become a ranking that holds up when judges run generous or strict and when some projects get more reviews than others.

1 · Weighted composite

Weight the criteria first

Each review is a weighted mean of the rubric criteria, kept on the 1 to 5 scale. Functionality 0.4, quality 0.4, innovation 0.2.

2 · Remove judge bias

Measure quality, not leniency

An additive model fits each judge's bias then subtracts it, so a project is scored on its own merit. A judge who scores everyone the same adds an offset and no ranking signal.

3 · Shrink by coverage

Coverage buys confidence, not rank

Each project's quality is pulled toward the mean by n/(n+k) with k = 0.81, so a noisy 2-review score cannot outrank a solid 5-review one.

Every score ships with an uncertainty band and its review count. Projects whose bands overlap are a statistical tie and go to a tie-break, not a decision on the third decimal. A guarded per-judge z-score runs as a cross-check. The full method with its references is in JUDGING.md.
The signed bundle

Everything needed to recompute, in one signed file

The bundle carries the raw scores, the rubric weights, the method with its parameters, the code commit and the ranking. It is hashed with sha256 over a canonical encoding then signed with Ed25519. The public key travels inside, so no key of ours is needed to check it.

Recompute the winner in your browser

This reruns the additive model on the 126 raw scores from the bundle, with no network, then checks the winner it produces against the published rank 1.

What the bundle holds

    Run verify.py

    The standalone checker, no portal needed

    Save the published bundle then run the verifier. It recomputes the ranking, checks the digest and verifies the signature. Standard library only, plus cryptography for the signature step.

    # save the published bundle
curl http://localhost:8080/api/results/bundle > bundle.json

# recompute the ranking, check the digest, verify the signature
python3 verify.py bundle.json
# -> VERIFIED   winner prj_16 (Salt Kiln)
    Change any score or rank in bundle.json and verify.py prints NOT VERIFIED, the same result as the live check above.

    Judge view

    A judge sees only their own scores

    Role isolation is enforced in the backend, not the template. the judge sees the reviews below and nothing from any peer.

    A judge asking for a peer's scores by id is refused with 403. That is the check most portals fail, so it lives in the backend behind a DRF permission class.
    curl -H "Authorization: Token judgeb…" \
  ".../api/judge/scores?judge_id=jdg_07"
# HTTP 403 Forbidden
    Results

    The ranking, with an uncertainty band per project

    Final score is mu plus the shrunken, bias-adjusted quality. The band and the review count show which ranks are solid and which lean on only a few reviews.

    Run it

    One command to a seeded, offline portal

    No cloud account, no hosted database, no external API. docker compose up builds one image, migrates, loads the fixture, generates a signing key on first boot then serves on localhost.

    docker compose up
# gallery      http://localhost:8080
# organizer    http://localhost:8080/admin/   (organizer / organizer)
# OpenAPI      http://localhost:8080/api/docs
    The acceptance checker is standard library Python: python3 spec/run.py .dogfood.toml makes seven HTTP requests as each role. The committed acceptance-report.txt shows 7 of 7 PASS at T1 and T2.
